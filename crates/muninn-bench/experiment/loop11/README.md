# Loop 11 — the value that is a number

Loops 8 and 9 are replacements of a *name*: `PgBouncer` → `Supavisor`, `jest` → `vitest`.
A large share of the decisions a team actually revises are not names but measured values — a
pool size, a timeout, a rotation threshold — and they behave differently in both halves of
the engine.

Ten scenarios, three phrasing styles, generated by `claude-haiku-4-5` after the engine was
read, each a number with its unit replaced by a different number of the same unit.

## In conversation

The rule is narrow on purpose: a message may retire a value only if it says **nothing but the
new value** ("bump to 7 attempts"), because one shared content word is below what the general
supersession rule asks for and lowering that floor was measured and rejected [Z5].

| | without the quantity rule | with it |
|---|---|---|
| retired, adjacent | 3/30 | **8/30** |
| retired, blocks | 1/30 | **6/30** |
| delivered, adjacent | 3/30 | **6/30** |

It costs nothing on the precision sets: `kept_a` is 15/15, 15/15 and 12/15 with the rule and
without it. Absolute recall is low because most of the generated phrasings say more than the
value ("We're hitting connection limits. Let me bump that up to 25"), and the guard against
walking onto another subsystem's budget is what keeps them out.

## In the code

A number is invisible to a diff read for *words*. The unit is on both lines and the number is
not a word at all, so `10 connections` → `25 connections` leaves nothing that went away: the
disappearance rule sees `connections` still in the tree and the swap rule sees `connections`
on both sides. Measured, before the quantity slot was read from the hunk: `both` retired
10/30 and delivered 9/30 — barely above the conversation alone.

Reading the hunk's two lines as quantity slots — same unit, different number — is the same
rule the conversation uses, applied to the diff:

| arm | retired | delivered |
|---|---|---|
| talk | 8/30 | 6/30 |
| code | 17/30 | 18/30 |
| both | **19/30** | **18/30** |
| noise | **0/30** | — |

Three of the thirty cells cannot pass: `24 hours` → `7 days` changes the unit as well as the
number, and a slot keyed on the unit cannot see that as the same decision.

Loops 8, 9 and 10 are unchanged by this: `both` 30/30 and 29/30 retired, 19/30 and 21/30
delivered, `noise` 0/30, and the three precision sets at 15/15, 15/15 and 12/15.

## Reproduce

```sh
for arm in talk code both noise; do
  python3 crates/muninn-bench/experiment/loop8/eval_all.py --muninn target/release/muninn \
      --arm $arm --order adjacent --commit-msg opaque \
      --phrasings crates/muninn-bench/experiment/loop11/heldout_phrasings.json \
      --scenarios crates/muninn-bench/experiment/loop11/scenarios.json --out /tmp/l11-$arm.json
done
```

## One extension that was tried and is not here

Half the generated phrasings state the new value without its unit — "Increase to 25.",
"bump that up to 25" — and the rule cannot see them, because a quantity slot is a number
*followed by* a unit and there is none. A `bare_numbers` path was written for exactly that:
extract a message that states a number and nothing else, and match it against the most recent
record that states one, with or without a unit.

Measured on this held-out set, it moved `retired` from 8/30 to 8/30 and `delivered` from 6/30
to 6/30. On the `both` arm it moved one cell and then moved it back. It is not in the engine.

The reason is worth keeping: the first message of those pairs — "Set pool size to 10." — puts
its number at the *end* too, so neither side has a unit and the only thing relating them is
that both contain a number. That is the anaphora relaxation loop 6 already measured and
rejected, arriving by another road.
